# Qwen3 的循环隐式推理蒸馏与 dLLM 后训练启发

- 状态：研究提案；尚未训练模型、复现实验或测量性能。
- 文献核对日期：2026-09-04。
- 初始模型与教师：`Qwen/Qwen3-1.7B`；教师使用显式 thinking 模式。
- 核心目标：在明确的任务分布、硬件与服务负载下，降低推理成本，同时尽量保留长 CoT 教师的准确率。

## 1. 研究问题与核心假设

能否从一个普通 Transformer 的现有权重出发，训练循环隐式推理学生，使其用较少的串行计算步骤替代教师的显式 CoT？进一步，能否借鉴 diffusion LLM（下称 dLLM，主要指 masked diffusion）的后训练方法，让模型学会有效更新 latent、提前获得正确答案，并按问题分配计算预算？

这里包含三个需要分别验证的问题：

1. **架构迁移**：普通预训练模型能否稳定地重复使用同一组层？
2. **计算压缩**：显式 CoT 中哪些依赖可以压缩或并行，哪些必须保留串行计算？
3. **预算优化**：在准确率约束下，何时停止，以及应使用多少 latent 位置和循环次数？

优先检验的假设是：

> 在相同后训练计算预算下，答案奖励 RL 加上经过验证的高预算到低预算自蒸馏，能否让 4 轮学生达到仅答案奖励 RL 的 8 轮学生的准确率，并保留分布外表现？

轮数是初始实验档位，不是性能预测。若假设成立，再检验自适应预算是否优于固定预算曲线。第一阶段保留完整参数规模，以区分 CoT 压缩与参数压缩的影响。

## 2. 已有证据与尚未解决的问题

| 工作 | 已有证据 | 对本提案的边界 |
| --- | --- | --- |
| [Reasoning with Latent Thoughts](https://arxiv.org/abs/2502.17416) | 循环结构具备模拟 CoT 的表达能力 | Theorem 5.4 的构造使用与 CoT 步数对应的循环和 dummy 位置；不是任意长 CoT 可以压缩成几个 loop 的证明 |
| [Relaxed Recursive Transformers](https://arxiv.org/abs/2410.20672) | 从普通预训练模型初始化共享层结构，并用深度相关 LoRA 恢复能力 | 主要支持权重共享与模型压缩，不能据此推断 CoT 已被压缩 |
| [LoopUS](https://arxiv.org/html/2605.11011v1) | 将 Qwen3-1.7B 等模型改造成编码、循环处理、解码结构，并进行后训练 | 已有相同 backbone 的改造先例；论文没有覆盖专门的长数学 CoT 压缩验证 |
| [CODI](https://arxiv.org/abs/2502.21074) | 同一个模型承担显式与隐式 CoT 任务，通过隐藏状态自蒸馏 | 支持同规模教师的可行性；不能保证所有任务、模型规模都能等精度压缩 |
| [LOTUS](https://arxiv.org/html/2606.31779v1) | 循环更新并行 latent 工作区，并用 CoT token 监督 | 提供最贴近的算法起点，但其结果不是本提案在 Qwen3 上的复现 |
| [LoopFormer](https://arxiv.org/abs/2602.11451) | 用时间、步长条件与一致性训练支持可变循环预算 | 可借鉴预算条件和跨深度训练，不能将从头训练结果直接等同于低成本架构改造 |

LOTUS 在 Llama-3.2-3B 的 GSM8K 自然语言 CoT 设置下报告 68.13% 准确率，显式 CoT 为 68.41%，思考阶段延迟约降低 6.9 倍。这是特定基准和测量条件下的证据；其速度测量采用单卡 H100、batch size 1，思考阶段加速不等于所有负载下的端到端成本降低。

该方向已有明确先例，研究贡献不能仅表述为“把 Qwen3 改成 loop，再做蒸馏”。更有价值的是在受控预算下证明计算压缩、过程学习和自适应预算的增量效果。

## 3. 架构：先压缩显式推理，再压缩权重

### 3.1 推荐起点：完整权重与循环 latent 工作区

令问题为 $x$，最终答案为 $y$，latent 工作区为 $Z_r\in\mathbb R^{M\times d}$。

```text
问题 x ── 计算一次问题前缀缓存 ───────────────────────────┐
                                                        │
初始化 latent Z0 → 共享模型更新 → Z1 → … → ZR → 答案解码 → y
```

第一版参考 LOTUS：保留 Qwen3 的完整 Transformer 权重，复用问题前缀缓存，只对 latent 区域进行重复处理，最终根据 latent 解码答案。初始化、最终 latent 缓存构建和读出所需的额外前向也必须计入成本。

- $M$ 控制并行工作区大小，$R$ 控制循环计算深度。
- 首先选择少量固定预算，暂不引入随机 latent 更新、动态稀疏计算或复杂停止策略。
- 训练时 latent 只能从问题和模型自身计算获得；教师 CoT 与答案标签不能作为学生 latent 的可见输入。
- 答案 teacher forcing 可以使用已生成的答案前缀，但 latent 工作区不能看到答案后缀。
- 如果采用预算条件，记录预算是否会改变早期更新：预算为 8 时的第 2 轮状态，不一定等于独立预算为 2 的执行结果。

若每个 latent 位置通过 LM head 监督一个 CoT token，工作区需要覆盖被监督的位置。不能用 32 个单 token 读出位置完整监督 512 个 CoT token。先用足够大的工作区验证并行收益，再通过步骤级对齐或训练专用重建模块研究更强压缩。

### 3.2 第二阶段候选：折叠中间层

[官方配置](https://huggingface.co/Qwen/Qwen3-1.7B/blob/main/config.json)给出 28 层、hidden size 2048，以及共享输入输出 embedding。一个待验证的候选拆分是：

```text
前 4 层 → 10 层共享块 × 2 → 后 4 层
```

展开深度仍为 28 层，但只有 18 层独立 Transformer 权重。按官方配置估算，忽略新增适配器，参数量约从 1.72B 降至 1.22B；每 token 的主体计算量仍接近原模型。该拆分不是已有最优结论。

初始化可以比较原层选择与共享权重加深度 LoRA；先恢复正常语言建模和显式回答能力，再与 latent 推理组合。不要将折叠失败解释为隐式推理本身不可行。

### 3.3 需要区分的缓存语义

“在固定 latent 区域反复计算”与“每个生成 token 都经过额外循环深度”是不同设计。对于后者，各循环深度的 KV 状态通常不同，不能因为权重共享就直接复用同一个缓存；LoopUS 附录 A.4 使用独立的深度缓存。对于前者，也必须区分可复用的问题前缀缓存与需要重建的 latent 缓存。

## 4. dLLM 的 RL 能借鉴什么

| 机制 | dLLM 中的对应问题 | 本提案的迁移方向 |
| --- | --- | --- |
| 后期状态监督早期状态 | 后期 denoising 状态提供更充分的上下文 | 高预算 loop 的答案分布监督低预算 loop |
| 中间状态信用分配 | 终点奖励不能区分各次填充的作用 | 比较立即回答与继续计算的最终收益 |
| 轨迹一致性 | rollout 与优化使用不同的掩码、步长或轨迹 | 优化时真实执行学生的循环路径 |
| 计算预算策略 | 调整 denoising 次数或提交位置 | 选择循环次数、停止时间，后续扩展到工作区大小 |

以下迁移方案是设计推演，尚未在本模型上验证。

### 4.1 保留可计算的答案概率

如果 latent 更新是确定性的，答案仍自回归生成，那么固定预算下：

$$
\pi_\theta(y\mid x,R)=\prod_t p_\theta(y_t\mid x,Z_\theta^{(R)}(x),y_{<t}).
$$

可以直接根据采样答案的奖励优化 $\log\pi_\theta$，并通过计算图对循环参数求导。最终奖励本身不需要可微。终点奖励没有显式标注每轮贡献，不代表前面的循环没有梯度。

dLLM 的最终文本概率通常难以直接计算，因此 [d1](https://arxiv.org/abs/2504.12216) 和 [ESPO](https://arxiv.org/abs/2512.03759)采用概率代理；[StableDRL](https://arxiv.org/abs/2603.06743)进一步研究估计比率的噪声和训练失稳。当前确定性 loop 加自回归答案头的设计不必引入这些代理。

优化时固定采样到的离散答案前缀，用当前参数从问题出发重算 latent，才能得到当前策略对自身循环路径的完整梯度。把 rollout 时保存的 latent 或 KV 当常量，是截断近似，应与完整梯度版本区分。

每轮通过 LM head 得到的辅助分布，也不自动构成实际生成策略的概率因子。如果只从最后一轮采样答案，不能直接把所有轮次的 log-prob 相加并声称它是部署策略的真实 log-prob。

### 4.2 高预算到低预算自蒸馏

[dOPSD](https://arxiv.org/abs/2607.04428)利用学生实际 denoising 轨迹的后期预测监督早期预测，并在主要训练设置中验证最终答案。可迁移为：

1. loop 学生在高预算下生成答案，并记录可用的中间状态。
2. 验证最终答案；错误高预算输出不作为正向蒸馏目标，但仍可参与有明确失败奖励的 RL。
3. 低预算学生在自己的真实执行路径上预测答案。
4. 在相同答案前缀下，对齐高、低预算答案分布，教师分支停止梯度。

候选损失为：

$$
\mathcal L_{\mathrm{depth-KD}}
=\mathbf1[\text{高预算答案正确}]
\sum_t D_{\mathrm{KL}}\left(\operatorname{sg}[p_{R_{\mathrm{hi}},t}]\;\|\;p_{R_{\mathrm{lo}},t}\right).
$$

先确认高预算在验证集上有优势，再开展深度蒸馏。若高预算没有增益，蒸馏不能凭空创造可压缩的额外能力。保留高预算的任务损失，并监测低预算训练是否损害高预算准确率。

初期用经过验证的高预算答案前缀提高稳定性；后续比较学生生成的答案前缀，以检验部署时的状态分布偏移。多轮自蒸馏可采用冻结快照或 EMA 教师，但应分别记录稳定性与成本。

不要求不同正确解法的 hidden state 逐元素一致，也不默认平均多个正确路径的 hidden state 仍是一条有效路径。

### 4.3 学习继续计算的价值

[DiSPO](https://arxiv.org/abs/2602.06462)在中间 diffusion 状态上进行局部分支；[EGSPO](https://arxiv.org/abs/2603.12554)研究按去噪步骤分解的优势信号。对 loop，可在少量抽样状态上比较“现在回答”与“继续若干轮后回答”。

用答案验证结果估计：

$$
Q_{\mathrm{continue}}(Z_r)-Q_{\mathrm{stop}}(Z_r)>\lambda\Delta C
\quad\Rightarrow\quad\text{继续计算}.
$$

这里的 $Q$ 是最终任务收益的条件期望，$\Delta C$ 是额外计算成本。训练轻量停止头近似这个比较，推理时不执行所有评估分支。训练期间分支解码的成本必须计入训练预算。

早期 latent 未必天然适合答案读出，需要先训练多深度读出能力。熵、状态距离、答案一致性可以作为停止头的特征，但不能直接当作正确性奖励；不得要求每轮都更自信或逐元素更接近某个固定表示。

已有 [RLTT](https://arxiv.org/abs/2602.10520)直接针对 LoopLM 使用多深度预测的加权学习信号。将其作为中间监督基线；区分这种辅助目标与实际终点采样策略的 policy gradient。

### 4.4 成本必须成为可学习决策的结果

候选优化目标是：

$$
J=\mathbb E\left[\mathbf1[\text{答案正确}]-\lambda C\right].
$$

如果所有样本固定执行相同轮数、使用相同工作区，循环成本分量是常数，单独惩罚它不能教会模型少算。第一版先固定工作区，让一个预算选择器根据问题采样 $R\in\{2,4,8\}$：

$$
\pi_{\theta,\phi}(R,y\mid x)=g_\phi(R\mid x)\,\pi_\theta(y\mid x,R).
$$

预算与答案都有明确概率。先分别建立各固定预算的能力，再训练选择器；随后才考虑逐轮停止或更新哪些 latent 位置。若随机控制影响执行路径，必须记录实际控制动作及其概率。

先恢复准确率，再逐渐提高成本权重。以验证集准确率约束选择工作点，避免通过快速输出错误答案获得表面上的成本收益。成本应反映目标负载下的测量或校准值，不能只统计可见 token。

## 5. 蒸馏与 RL 的分阶段训练

| 阶段 | 训练内容 | 进入下一阶段的条件 |
| --- | --- | --- |
| A：教师与基线 | 原版 Qwen3 生成显式 CoT，验证答案；建立 no-thinking、短 CoT、长 CoT 曲线 | 教师在目标任务上有足够的正确监督，基线成本可复现 |
| B：latent 能力初始化 | 答案 CE，逐步加入答案分布蒸馏及 CoT 过程监督 | 学生在隐藏 CoT 输入后仍能有效答题，循环运行稳定 |
| C：固定预算 RL | 用最终答案验证奖励训练各固定预算，梯度穿过循环 | 相比蒸馏 checkpoint 有稳定收益，或明确识别失败原因 |
| D：跨深度蒸馏 | 经过验证的高预算学生监督低预算学生 | 低预算准确率提高，且不是以大幅损害高预算为代价 |
| E：自适应预算 | 学习预算选择或停止策略 | 同平均实测成本优于固定预算方案 |
| F：权重压缩 | 折叠中间层，恢复能力，重新评估整条曲线 | 明确分离参数压缩与计算压缩的效果 |

阶段 B 的候选组合损失：

$$
\mathcal L=\mathcal L_{\mathrm{answer}}
+\lambda_{\mathrm{KD}}\sum_t D_{\mathrm{KL}}\left[p_T(\cdot\mid x,c,y_{<t})\;\|\;p_S(\cdot\mid x,Z_R,y_{<t})\right]
+\lambda_{\mathrm{process}}\mathcal L_{\mathrm{process}}.
$$

$c$ 为教师 CoT，仅教师可见。先做答案监督，再分别加入 KL 和过程监督，避免无法归因的复杂组合。教师、学生参数相同规模不构成障碍，教师可以因更长思考而具有优势；但不能从教师频繁失败的题目中期待稳定的正确过程监督。

第一轮不引入整个高维 latent 的强随机扰动。[Latent-GRPO](https://arxiv.org/abs/2604.27998)在 vocabulary-mixture latent 设置中报告探索与有效表示区域的冲突；这不是所有 loop 的定理，但支持先从预算等结构化离散决策开始探索。固定问题和预算下的确定性 latent 路径相同，多次采样答案不等于采样了多条 latent 思路。

## 6. 成本核算与 Pareto 定义

参数量、FLOPs、串行步骤、延迟、吞吐和 KV 显存是不同指标。

令教师 CoT 长度为 $N$，学生工作区为 $M$，对工作区的完整处理次数为 $R$。相同宽度与处理深度下，仅用主导的投影和 FFN 计算作粗略近似：

$$
F_{T,\mathrm{think}}\propto N,\qquad F_{S,\mathrm{think}}\propto RM.
$$

| 示意配置，非测量结果 | 主体计算的粗略单位 | 串行处理阶段 |
| --- | ---: | ---: |
| 教师生成 512 个 CoT token | 512 | 512 次 token 解码 |
| 32 个 latent，完整处理 8 次 | 256 | 8 轮 |
| 128 个 latent，完整处理 8 次 | 1,024 | 8 轮 |

该近似不包含注意力长度、输出头、额外缓存构建和硬件调度，不能直接换算加速倍数。最后一行可能延迟更低但 FLOPs 更多。反复重算整个问题前缀也可能消除收益。

测量应包含问题 prefill、全部 latent 计算、最终答案生成和额外调度，报告：

- 同一硬件、精度和服务实现下的单请求端到端延迟，以及 p50/p95。
- 多个并发水平下的吞吐与每请求 GPU 时间，区分低并发和饱和负载。
- 峰值显存、KV 大小、全部输出 token、循环数与工作区大小。
- 教师数据生成、验证、RL rollout、分支评估、训练和调参的预算。

相对原模型默认长 CoT 更快，不足以证明推进前沿。应比较所有基线及其预算配置形成的非支配点集合，并区分“新增较快但略低准确率的工作点”与“同时改善准确率和成本”。有限实验只能支持所测模型、任务和负载范围内的经验前沿结论。

## 7. 最小实验矩阵与评估协议

| 编号 | 实验 | 归因问题 |
| --- | --- | --- |
| B0 | 原版 no-thinking、短预算、长预算 CoT | 原模型的完整预算曲线 |
| B1 | 普通架构 answer-only 蒸馏，及其答案奖励 RL 版本 | 收益是否仅来自任务后训练 |
| B2 | CODI 式自回归 latent 蒸馏 | 并行工作区循环的增量价值 |
| L0 | loop 学生，仅答案监督 | 架构自身的贡献 |
| L1 | L0 加答案分布、过程蒸馏的独立消融 | 哪种监督有效 |
| L2 | 最佳蒸馏版本加固定预算答案 RL | 最简单的 RL 能否改善性能 |
| L3 | L2 加跨深度自蒸馏 | 是否将高预算收益提前 |
| L4 | L3 加预算选择；后续再加停止头 | 同成本下是否改善固定预算曲线 |
| L5 | 最佳方案加共享层压缩 | 参数压缩的独立贡献 |

第一轮使用 $R\in\{1,2,4,8\}$ 的少量档位，工作区按监督长度设置。预算选择器可先使用已表现出差异的子集。固定工作区完成深度消融后，再研究工作区大小。

评估要求：

1. 使用可验证的数学或结构化推理任务做起点。GSM8K 用于初步验证；再扩展至 MATH、更多推理步骤、数字变化与题目改写。外推与改写集合应检查与训练集的重叠。
2. 同一数据来源下报告实际训练计算量。不同方案若无法完全匹配，给出预算差异，不能只匹配优化步数。
3. 对照使用相同 prompt、答案格式、解码规则、最大长度、精度与验证器。测试失败、超时和未完成答案计入，不从分母删除。
4. 超参数与 checkpoint 仅按验证集选择。确认候选后用多个随机种子复核，并报告配对置信区间。
5. 统计完整答案正文，避免把 CoT 移到答案区后误称无显式推理或省 token。
6. 比较完整循环梯度与冻结 latent 的截断版本；对少量样本进行替换、打乱或重置 latent 的干预，以确认输出实际依赖 latent 计算。
7. 单独记录被教师正确性筛选排除的题目难度。训练筛选不改变测试分布。

可预注册一个初始工程目标：相对长 CoT 教师，准确率下降不超过 1 个百分点，端到端延迟至少降低一半。此数值是待验证阈值，不是预测；统计不确定性与分布外准确率应共同决定是否达标。

## 8. 失败条件与下一步决策

| 观察 | 优先解释与后续动作 |
| --- | --- |
| 增加循环始终没有准确率收益 | 先解决循环利用和稳定性；暂不开展高到低预算自蒸馏 |
| 答案准确率提高，但重置 latent 几乎无影响 | 可能主要学会了直接回答；检查普通架构基线和计算图 |
| 低预算在域内提升、长推理外推下降 | 可能压缩掉必要串行计算；保留预算适应能力，扩大难度覆盖 |
| 仅 batch size 1 更快，满负载更贵 | 收益属于低延迟场景；按负载分别报告前沿 |
| 自适应预算不优于固定预算包络 | 选择器没有有效识别额外计算价值；检查价值估计和调度开销 |
| RL 提高奖励但循环次数或正文暴涨 | 检查奖励定义，计入全部计算与输出，重新选验证工作点 |
| 仅复杂组合有效，单项贡献不稳定 | 增加最关键的消融，避免将偶然训练优势归因于某个机制 |

最优先的下一项工作是建立 Qwen3-1.7B 的可复现基线和最小循环学生，再检验高预算是否具有可蒸馏的优势。只有确认这一点，才值得增加过程评估、停止策略与参数折叠。
